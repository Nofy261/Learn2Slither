La formule du Q-learning :
nouvelle_valeur = ancienne_valeur + (reward + meilleure_valeur_future - ancienne_valeur)

Le reward c'est le signal d'apprentissage — c'est grâce à lui que les valeurs dans 
  la Q-table changent et que le serpent devient plus intelligent !
Sans reward → pas d'apprentissage → le serpent reste stupide

new_value = old_value + learning_rate × (reward + gamma × meilleure_valeur_future - old_value)

learning_rate → à quelle vitesse le serpent apprend (ex: 0.1)
gamma → à quel point il se souvient du futur (ex: 0.9)
reward → ce qu'il a gagné ou perdu maintenant

state c'est ce que le serpent voit (True, False, ....)
[0, 0, 0, 0] -> c est les scores des 4 actions


Dans la Q-table => self.table[state] = [0, 0, 0, 0] 
---> Pour cette situation → voilà les scores des actions


self.table[state] → on accède au dictionnaire à la clé state → on récupère [0, 0, 0, 0]
self.table[state][action] → dans cette liste [0, 0, 0, 0] on accède à l'index action

self.table[state][action] =  self.table[state][0] = 2.5

Au début, epsilon est grand, donc le snake explore beaucoup car il ne connaît rien encore.
Au fur et à mesure des sessions, on diminue epsilon, donc le snake exploite 
de plus en plus ce qu'il a appris. C'est l'algorithme epsilon-greedy.
------

epsilon_decay — c'est quoi ?
C'est le multiplicateur qu'on applique à epsilon après chaque session
pour le diminuer progressivement.
C'est la vitesse à laquelle epsilon diminue après chaque session.

La formule dans decay() sera :
self.epsilon = self.epsilon * self.epsilon_decay

Exemple  avec 0.995
Session 1  →  epsilon = 0.9
Session 2  →  epsilon = 0.9 × 0.995 = 0.8955
Session 3  →  epsilon = 0.8955 × 0.995 = 0.8910
Session 4  →  epsilon = 0.8910 × 0.995 = 0.8865
...
Session 100 → epsilon ≈ 0.44
Session 500 → epsilon ≈ 0.08  (< 0.1 → on reste à 0.1 minimum)
--------

reduce_epsilon():
Session 1  →  snake joue  →  game over  →  decay()  →  epsilon = 0.9 × 0.995 = 0.8955
Session 2  →  snake joue  →  game over  →  decay()  →  epsilon = 0.8955 × 0.995 = 0.8910
Session 3  →  snake joue  →  game over  →  decay()  →  epsilon = 0.8910 × 0.995 = 0.8865
...
quand la partie est terminée -> epsilon change.
--------

gamma = 0.9 signifie : "Le futur compte, mais moins que maintenant"

gamma = 0   →  le snake ne pense qu'au présent
gamma = 1   →  le futur compte autant que le présent
gamma = 0.9 →  bon équilibre
--------

learning_rate grand (ex: 0.9)  →  apprend vite mais instable
learning_rate petit (ex: 0.1)  →  apprend lentement mais stable et précis
C'est comme apprendre à conduire :
Si on corriges trop fort le volant → on zigzagues
Si on corriges doucement → on restes stable
On utilise 0.1 — bon équilibre.

Formule de Bellman expliqué:
"Ce que je pensais de cette action" + "ce que j'ai vraiment gagné" + "ce que je pourrais gagner ensuite"

La formule de Bellman répond à cette question : "Combien vaut cette action dans cette situation ?"
------

(reward + gamma × best_future - old_value) en mot simple
C'est l'écart entre ce qu'on espérait et ce qu'on a vraiment eu.

old_value → ce qu'on pensait que ce pas valait avant de le faire
reward + gamma × best_future → ce que ce pas vaut vraiment (ce qu'on a gagné + ce qu'on pourra gagner ensuite)
La soustraction → l'erreur : "j'avais tort de combien ?"

Exemple :
old_value = 0.0    # on pensait que UP ne valait rien
reward + gamma × best_future = 0.72   # en réalité ça valait 0.72

écart = 0.72 - 0.0 = 0.72  # on s'était trompé de 0.72
Et learning rate contrôle à quelle vitesse on corrige cette erreur :

nouvelle_valeur = 0.0 + 0.1 × 0.72 = 0.072
On ne corrige pas tout d'un coup (sinon un seul mauvais coup effacerait tout l'apprentissage).
-------

gamma pondère l'importance du futur (0 = aveugle, 1 = futur compte autant que maintenant)
reward + gamma × best_future = ce que le pas vaut vraiment
- old_value = l'erreur qu'on a faite, et lr contrôle à quelle vitesse on la corrige
----------------

Learning rate => En résumé :

lr contrôle la fraction de l'erreur qu'on corrige à chaque pas
Si old_value trop haute → la valeur descend
Si old_value trop basse → la valeur monte
Avec le temps la valeur converge vers la vraie valeur
DONC learning_rate sert a corriger l'erreur petit a petit
----------

FORMULE DE BELLMAN: explication

nouvelle_valeur = 2.1 + 0.1 × (1.45 - 2.1)
2.1 → ce qu'on pensait que ce pas valait avant de le faire
1.45 → ce que ce pas vaut vraiment (reward + gamma × best_future)
(1.45 - 2.1) → l'erreur qu'on a faite, on s'était trompé de -0.65
0.1 → on ne corrige que 10% de cette erreur, petit à petit
nouvelle_valeur → la valeur corrigée qu'on stocke dans la Q-table
En une seule phrase :

"Je pensais que ce pas valait 2.1, en réalité il vaut 1.45, je me suis trompé de -0.65,
donc je corrige 10% de cette erreur et je mets à jour ma Q-table avec 2.035."
